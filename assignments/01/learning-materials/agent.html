Agent 概念学习资料

概念 AI / 大模型 生成于 2026-09-04 · 使用 concept-study-pack Skill

学完这份资料，你将能用自己的话讲清楚什么是 AI Agent、它由哪些部件组成、能用在哪些真实场景里，以及它和普通 LLM 对话、Copilot 的边界在哪里。

1. 学习目标

学完后你应该能够：

  1. 用自己的话解释"AI Agent 是什么"以及它和普通聊天机器人的核心区别。
  2. 拆解 Agent 的四大组成要素（LLM / 记忆 / 规划 / 工具），并描述它们如何协作完成一个多步任务。
  3. 举出 3 个真实存在的 Agent 应用场景，并说明它们解决了什么问题。
  4. 辨析 Agent、LLM、Copilot、Workflow 四个易混概念，能说出适用前提和失效条件。
  5. 理解 ReAct 推理-行动循环的工作方式，能描述一次完整的"思考→行动→观察"周期。

2. 核心问题

带着这 5 个问题阅读下面的内容：

  1. Agent 解决的是什么问题？普通 LLM 对话为什么不够用？
  2. Agent 是怎么"自主"的？谁决定下一步该做什么？
  3. Agent 内部由哪几块组成，它们之间怎么配合？
  4. Agent 调用外部工具时，背后发生了什么？
  5. Agent 一定会成功吗？什么情况下它会失败？

3. 个人解释

一句话：Agent 是一个以大模型为"大脑"、能自主决定下一步动作、并能用工具影响外部世界的程序。它和 ChatGPT 的根本区别是——它会自己"做"，而 ChatGPT 只会"答"。

把这件事想成你雇了一个新员工。普通 LLM 对话就像你不断问这位员工"这道题怎么做"——他给你答案，但事情做没做、做得对不对，他不管。Agent 则是你给他一个目标（"帮我订明天从北京到上海最便宜的高铁票"），他自己会拆解任务、查时刻表、比对价格、调用支付接口、订票，遇到问题再回来找你。

这种"自主"并不是玄学，它来自三个具体能力：(1) 规划——把大目标拆成小步骤；(2) 工具——能调外部 API、读文件、写代码、执行命令；(3) 反馈——根据工具返回的结果决定下一步。一个最小可工作的 Agent 就是：LLM + 规划循环 + 工具接口 + 上下文窗口。OpenAI 把它简化为"模型 + 工具 + 指令"三件套，Anthropic 进一步区分"Workflow（按预设路径走）"和"Agent（按环境反馈自主走）"——这正是当前业界最常引用的两个定义。

4. 核心机制

Agent 的经典公式来自 OpenAI 研究员 Lilian Weng：Agent = LLM（大脑） + 记忆 + 规划能力 + 工具使用。下面是各组件的拆解：

4.1 四大组成要素

要素作用常见实现
LLM（大脑） 负责理解指令、做规划、决定下一步动作、生成回应文本 GPT-4、Claude、Gemini、Llama 等基座模型

工具（Tools） 让 LLM 触达外部世界：搜索、读写文件、调用 API、执行代码 Function Calling、Tool Use、Computer Use、MCP 协议

5. 应用场景

  1. 软件工程 - Devin / Cursor / GitHub Copilot Agent
    谁在用：Cognition Labs（Devin）、Anysphere（Cursor）、GitHub。
    解决什么：从 issue 描述到自动修改代码、提 PR、执行测试。
    效果：Devin 演示中可独立完成"分析 bug → 写修复 → 跑测试"全流程；Cursor 在 IDE 内做跨文件代码改动。
  2. 通用任务执行 - Manus / OpenAI Operator / Claude Computer Use
    谁在用：创业公司（Manus）、OpenAI、Anthropic（2024 年 10 月推出 Computer Use）。
    解决什么：用户给一个高层目标，Agent 自己拆任务、操作浏览器或桌面应用完成。
    效果：在 SWE-bench 等基准上，已能从 2023 年个位数正确率提升到 2025 年的 50%+。
  3. 深度调研 - ChatGPT Deep Research / Hugging Face Open Deep Research
    谁在用：OpenAI（2025 年 2 月发布）、Hugging Face（2025 年 2 月开源）。
    解决什么：用户提出开放性问题，Agent 自动检索多源、交叉验证、生成结构化研究报告。
    效果：相比单次对话，能跨数十个网页整理信息并附引用。
  4. 客服与运营自动化 - Salesforce / Zendesk / 阿里千问 / 字节 Coze
    谁在用：企业 SaaS 厂商、客服中心。
    解决什么：自动接待、查询订单、调取 CRM 数据、升级人工。
    效果：Zendesk 报告显示，AI 客服可独立解决 60-80% 的常见工单。
  5. 多 Agent 协作 - Microsoft AutoGen / LangGraph / CrewAI
    谁在用：研究机构、企业研发团队。
    解决什么：让"需求分析 Agent / 编码 Agent / 测试 Agent"分工协作。
    效果：在软件交付、数据分析、报告生成等任务上，单 Agent 不擅长处理的多步流程得以分解并行。

6. 概念辨析

6.1 它是什么 / 不是什么

Agent 是：以 LLM 为推理核心、能自主决策调用工具并对外部世界产生作用的程序系统。

Agent 不是：一个有意识的存在，也不是"AGI"，也不是简单"调一次 API 的 LLM"。它的自主性受限于 LLM 能力、工具范围和上下文窗口。

6.2 易混对照表

维度LLM 对话CopilotWorkflowAgent
触发方式用户每轮输入用户输入 + 触发条件事件 / 数据流入用户给定目标
决策权用户决定下一步用户主导，AI 辅助代码预定义路径LLM 动态决定
工具调用不调用有限补全按预设调用自主选择调用
多步任务不擅长辅助完成擅长确定性流程擅长开放式任务
可预测性中等较高最高较低
怎么区分你问它答它建议你写流水线按图施工它自己拆活自己干

6.3 适用前提与失效条件

适用前提：任务有清晰的成功标准、可以分解为可观测的步骤、配套工具 API 完备、允许若干次试错。
失效条件：
  • 任务没有可验证的成功标准（Agent 无法判断自己做得对不对）。
  • 关键工具 API 不稳定或权限不可控（Agent 会反复失败）。
  • 上下文窗口严重不足、需要长期记忆的任务（Agent 会"失忆"）。
  • 对成本和延迟敏感的场景（多步循环会放大 token 和算力开销）。
  • 高风险领域（医疗诊断、关键基础设施）——尚需人在回路（Human-in-the-Loop）把关。

6.4 常见误解

  • 误解 1："Agent = AGI"。纠正：Agent 是工程产物，受限于 LLM 与工具；AGI 强调通用智能水平。
  • 误解 2："Agent 一定能完成任务"。纠正：Agent 经常陷入循环、调用错的工具或编造结果，必须配评估/兜底。
  • 误解 3："只要换更大的模型 Agent 就更强"。纠正：工具质量、规划策略、上下文管理同样关键；小模型配合好工具也能胜过大模型裸跑。

7. 自测题

先做题，再点开看答案。

Q1（概念复述）：请用一句话向完全不懂 AI 的朋友解释"AI Agent 是什么"。

参考答案：Agent 是一个有"自己想办法"能力的 AI 程序——你给它一个目标，它会自己拆步骤、用工具、把事情做完；普通聊天 AI 只会回答问题，而 Agent 会"动手"。

Q2（组成要素）：Agent 的四大组成要素是什么？它们各起什么作用？

参考答案：LLM（大脑，做推理和决策）、记忆（短期是上下文窗口、长期是向量库）、规划（拆任务、ReAct/CoT）、工具（Function Calling、调 API、执行代码）。它们协作形成"想→做→看→再想"的循环。

Q3（机制应用）：请描述 ReAct 循环的三个阶段，并用"订一张明天去上海的高铁票"举例说明一轮循环。

参考答案：三个阶段是 Reason（推理下一步要做什么）→ Act（调用工具，如 12306 查询接口）→ Observe（读取返回的车次列表，更新上下文）。下一轮再 Reason，从结果中选最合适的车次并下单，直到完成或达到步数上限。

Q4（应用判断）：公司让你做一个"自动从客户邮件中提取订单并写入 ERP"的功能。你会选 Workflow 还是 Agent？为什么？

参考答案：优先选 Workflow。任务清晰、步骤可枚举、容错低（写错 ERP 的代价大），用 Workflow + LLM 抽取字段更稳定；只有当邮件格式高度多样且没有模板可参考时，再考虑用 Agent 兜底。

Q5（边界辨析）：有人说"只要 LLM 够强，所有应用都该用 Agent"。这个说法对吗？请用至少一条边界条件反驳。

参考答案：不对。Agent 的成本高（多轮 token 累积）、延迟大（每步往返）、可预测性差；对实时、低成本、确定性场景（如接口鉴权、高频交易）反而不适合。LLM 强 ≠ 任务就一定要 Agent 化。
