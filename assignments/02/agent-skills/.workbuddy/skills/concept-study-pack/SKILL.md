# 概念学习包生成 Skill (concept-study-pack)

## 概述

把任意一个陌生概念变成一份\"打开就能学、学完能复述\"的 HTML 学习包。它不止是定义摘抄，而是按学习路径组织：先定目标、提问题（让自己带着目的学），再用自己话讲明白、拆解机制、落到真实场景、辨清边界、最后用自测题巩固。每条关键论断附可核验来源，**禁止编造 URL**。

## 适用场景

满足以下任一条件时使用：

- 用户提出\"帮我学习 / 整理 / 讲清楚 / 做一份资料\"且对象是一个明确的单一概念。
- 用户在课程、阅读、调研中遇到陌生概念，希望系统化建立结构理解并留下可保存的 HTML 资料。
- 用户要求\"按固定结构生成学习包\"或\"做一份带自测题的概念卡\"。
- 用户提供概念名 + 少量背景（如\"我在学大模型，给我讲一下 LoRA\"），按背景适配深度。

不适用：纯事实查询（\"X 的版本号\"）、操作性任务（\"帮我装 X\"）、多概念对比专题（先对每个概念分别调用本技能，再做对比）。

## 输入信息

| 信息项 | 是否必需 | 缺省行为 |
|---|---|---|
| 概念名称 | 必需 | 反问 |
| 学习者背景 | 可选 | 默认\"具备通用知识、首次接触该概念\" |
| 深度偏好 | 可选 | 默认\"入门到能复述\"，含自测题但不展开公式/源码 |
| 输出文件名 | 可选 | 默认 `<概念名>.html`（小写、英文/拼音） |
| 附加关注点 | 可选 | 用户可特别要求\"偏实践 / 偏原理 / 偏历史\"，按关注点调整各板块权重 |

若只给了概念名，按缺省假设直接执行，并在输出中用一行说明本次使用的假设（不要为了问问题而中断流程）。

## 生成步骤

### 第 1 步：检索与核实

- 联网搜索该概念，覆盖三类来源：
  1. 权威定义（官方文档、教科书、学术论文、标准组织、Wikipedia）。
  2. 高质量解读（官方博客、知名技术媒体、专业社区深度文章）。
  3. 不同视角讨论（社区问答、实践者经验、对比类文章）。
- 中英文同时检索，确保术语翻译准确；英文专有名词记录中英对照。
- 把每个关键论断与对应 URL 记下来，供第 4 步引用。
- 检索不到支撑的论断，要么删除，要么在文中显式标注\"待核实的个人推断\"。

### 第 2 步：内化

在动笔前先回答三个问题（写到学习包的\"个人解释\"开头作为铺垫）：

1. 这个概念解决什么问题？它替代了原来的什么做法？
2. 核心机制一句话怎么说？
3. 没有它之前，人们怎么做、痛点在哪？

### 第 3 步：按八个板块生成

严格按下方\"输出结构\"的顺序与要求生成 HTML。HTML 必须是**单文件可离线打开**——CSS 内联、不依赖外部 CDN（图片用占位/纯文本/或 base64 内嵌）。

### 第 4 步：引用与自检

- 关键论断必须配 URL。
- 对照\"自检要求\"逐项检查，全部通过才交付。
- 检查完成后，把\"人工核查\"标记写进 HTML 末尾的\"核查记录\"小节。

## 输出结构

输出为**单文件 HTML**，UTF-8 编码、CSS 内联、不依赖外部资源（避免 CDN 失效导致样式丢失）。文件命名建议 `<概念英文或拼音>.html`（如 `agent.html`、`llm-context.html`）。HTML 内含以下八个板块，顺序固定：

### 1. 学习目标 (Learning Objectives)

3–5 条用动词开头的目标（解释 / 拆解 / 举例 / 辨析 / 应用）。每条一行。

### 2. 核心问题 (Driving Questions)

3–5 个学完应能回答的开放性问题，摆在最前面带着目的读。问题用 `<ol>` 列出，答案在对应板块里被解答。

### 3. 个人解释 (My Explanation)

- 完全用自己的话（不照抄百科），250–400 字。
- 必须含一个贴近学习者背景的类比（无背景时用日常生活类比）。
- 第一句要让完全外行抓住大意。
- 用第 2 步内化的\"三个问题\"做骨架。

### 4. 核心机制 (Core Mechanism)

- 拆解关键组成 / 运作流程 / 相互关系，**用结构化 HTML 呈现**（`<ol>`/`<ul>`/表格/SVG/Mermaid 中至少一种）。
- 若适合可视化，附一个简洁的 SVG 流程图或结构图（用内联 SVG，不引外链）。
- 每点 1–3 句，避免大段文字。

### 5. 应用场景 (Applications)

- 3–5 个真实、具体的应用场景。每条包含：
  - 谁在用（角色 / 产品 / 论文）
  - 解决什么问题
  - 效果或典型指标
- 场景必须经检索核实，禁止虚构案例与数据。

### 6. 概念辨析 (Boundaries & Confusions)

- \"它是什么 / 不是什么\" 一段。
- 2–3 组**易混对照表**：用 `<table>` 呈现\"A vs B\"，列：维度 / 概念 A / 概念 B / 怎么区分。
- 列出该概念的**适用前提**与**失效条件**（什么情况下用它不合适）。
- 标注 1–2 条常见误解并纠正。

### 7. 自测题 (Self-Check)

- 5 道题混合：3 道概念复述、1 道应用判断、1 道边界辨析。
- 题型建议：简答（2–3 句）、判断对错（含理由）、举例说明。
- 自测题紧跟**答案折叠区**（`<details><summary>显示答案</summary>...</details>`），先做题再看答案。
- 答案要点具体、含可核查信息（不可只写\"它是一种机制\"）。

### 8. 参考来源 (References)

- `<ol>` 列出，每条格式：`[<来源标题>](URL) — 一句话说明该来源支撑哪些板块。`
- 3–8 条，按权威性排序。
- 每条 URL **必须来自本次实际检索结果**，禁止凭记忆拼凑或编造。
- 时效性资料（AI、框架）注明资料时间或\"以官方最新文档为准\"。

### 末尾：核查记录 (Verification Log)

表格列出本资料的核查项：检索关键词、来源数量、关键论断是否均有支撑、是否有待核实推断、人工核查时间。

## 资料来源要求

- 优先级：官方文档 / 论文 / 教科书 > 权威机构或厂商博客 > 知名技术社区 / 专业媒体 > 个人博客 / 论坛问答。论坛与问答只能作辅助，不得作为唯一定义依据。
- 每条来源必须真实可访问：URL 来自本次实际检索结果，无法访问的来源不得列出。
- 关键论断（定义、机制、数据、案例）至少有一条来源支撑；检索不到支撑的论断要么删除，要么显式标注为\"待核实的个人推断\"。
- 时效性：AI、框架类工具优先近 1–3 年的资料，并提示读者以官方最新文档为准。
- 中英文来源均可；正文用自己的中文表述，不得整段翻译或照抄。

## 自检要求

交付前逐项核对，任何一项不通过则修改后重新检查：

1. **结构完整**：八个板块齐全，顺序正确，标题与编号符合本规范。
2. **HTML 自包含**：CSS 内联、无外部 CDN/字体/图片依赖；用浏览器直接打开样式正常。
3. **输入适配**：内容针对输入概念本身，无模板残留、无\"该概念\"空泛指代。
4. **个人解释质量**：无直接复制粘贴定义原文；外行读第一段能明白概念是什么。
5. **机制准确**：核心机制与权威来源一致；如有不确定，已在文中显式标注。
6. **场景真实**：所有应用场景可溯源，无虚构案例。
7. **边界清晰**：至少 1 组易混对照表 + 1 条适用前提/失效条件 + 1 条常见误解纠正。
8. **自测题质量**：5 题、含答案折叠、答案要点具体。
9. **来源可靠**：每条链接来自实际检索、格式正确、关键论断均有支撑。
10. **核查记录**：末尾有核查表格、含人工核查时间。

## 限制与边界

- **不替代人工核查**：本 Skill 输出仅供学习参考，关键事实（尤其在 AI 等快速演进领域）须以官方最新文档为准。
- **不生成未经核实的\"权威\"链接**：检索不到的来源宁可少列也不编造。
- **不输出长篇大段文字**：每个板块用结构化 HTML（列表 / 表格 / 折叠区）组织，避免大段 paragraph。
- **不支持批量**：每次输入一个概念，输出一个 HTML；多概念对比请多次调用后人工整合。
