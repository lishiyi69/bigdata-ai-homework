Skill 概念学习资料

概念 AI Agent / 模块化提示 生成于 2026-09-04 · 使用 concept-study-pack Skill

学完这份资料，你将能用自己的话解释"Skill（技能）"是什么、它的内部结构、它和 Prompt / Project / Subagent / MCP 的区别，以及它如何解决"团队经验沉淀"和"上下文占用"两个老大难问题。

1. 学习目标

  1. 用自己的话解释"Skill 是什么"以及它解决的核心问题（重复 prompt + 上下文浪费）。
  2. 描述一个 Skill 的标准结构（YAML 元数据 + Markdown 指令 + 可选脚本/资源）。
  3. 区分 Skill、Prompt、Project、Subagent、MCP 五个易混概念，能说出它们各解决什么。
  4. 理解 Skill 的"按需加载"机制如何节省上下文窗口。
  5. 知道 Skill 的适用场景（重复性任务、需要一致性的工作）和不适用场景（一次性探索）。

2. 核心问题

  1. 为什么 Anthropic / OpenAI / Cursor 等厂商要专门做"Skill"这个抽象？
  2. 一个 Skill 物理上长什么样？最少需要哪些文件？
  3. Skill 是怎么知道"该不该用"的？是用户手动指定还是自动触发？
  4. Skill 和一段长长的 system prompt 有什么本质区别？
  5. Skill 能解决上下文窗口压力吗？为什么？

3. 个人解释

一句话：Skill 是把"做某件事的最佳实践"打包成一个文件夹，让 AI Agent 在需要时按需加载、按说明执行——它是 AI 的"工作手册"，而不是"人设剧本"。

把这件事想成你给新员工编写的"操作 SOP"。一份好的 SOP 包含：标题（这份 SOP 是干嘛的）、适用场景（什么时候用）、具体步骤（先做什么后做什么）、配套资源（表单、脚本、模板）。Skill 就是给 AI 的 SOP，物理上就是这样的一个文件夹。

它和普通 prompt 的关键区别在于三件事：第一，按需加载——Skill 不一直在上下文里，Agent 只在判断"这个任务和某个 Skill 相关"时才把它读进上下文，省 token；第二，可复用——同一个 Skill 可以在多个会话、多个项目、多个 Agent 里使用，可以放进 Git 做版本管理、团队共享；第三，结构化——SKILL.md 顶部有 YAML 元数据（name、description、触发条件），机器可读，便于自动发现和路由。

Anthropic 在 2025 年 10 月正式推出 Agent Skills 时，把它定义为"包含指令、脚本、资源的文件夹，Claude 在需要时按需加载"——本质上是用文件系统+版本控制解决"AI 团队经验沉淀"问题。

4. 核心机制

4.1 一个 Skill 的标准结构

my-skill/
├── SKILL.md          # 必需：YAML 元数据 + Markdown 指令
├── scripts/          # 可选：可执行脚本
│   └── validate.sh
├── examples/         # 可选：示例输入/输出
│   └── good-output.md
├── templates/        # 可选：模板文件
│   └── report-template.md
└── LICENSE.txt       # 可选：许可证

4.2 SKILL.md 的 YAML 元数据

---
name: internal-comms
description: 一组帮用户撰写公司内部沟通的资料，按公司偏好格式输出。当用户要求写 3P 更新、公司通讯、FAQ、状态汇报等内部沟通时使用。
license: 完整条款见 LICENSE.txt
---

关键字段：

  • name：技能名（同文件夹名）
  • description：触发条件 + 用途说明。Agent 靠这段描述判断要不要加载
  • license / allowed-tools（可选）：限制 Skill 的能力边界

4.4 四大核心属性（Anthropic 总结）

属性含义
Composable（可组合）多个 Skill 可堆叠，Agent 自动协调使用
Portable（可移植）同一 Skill 可在 Claude.ai / Claude Code / API 中通用，格式统一
Efficient（高效）按需加载，只读入必要内容，节省上下文
Powerful（强大）可包含可执行代码，在 token 生成不如传统编程可靠的任务上发挥作用

5. 应用场景

  1. 企业品牌与格式规范
    谁在用：Box、Notion、Canva（Anthropic 客户案例）。
    解决什么：让 AI 生成的 PPT/Word/Excel 自动套用公司模板与品牌色。
    效果：Notion PM MJ Felix 称"减少 prompt 调教，输出更可预测"。
  2. 代码评审 / 团队工程规范
    谁在用：使用 Claude Code 的研发团队。
    解决什么：把团队的 PR Review 标准、命名规范、安全检查清单做成 Skill，AI 自动按规范评审。
    效果：每次评审都一致；新人也"自动"按老规矩写代码。
  3. 金融建模与财务分析
    谁在用：Anthropic 内置 Skill + 第三方。
    解决什么：DCF、Comps Analysis 等重复性分析流程模板化。
    效果：Anthropic 客户 Kaji 反馈"原本 1 天的管理工作 1 小时完成"。
  4. 研发工作流自动化（Claude Code）
    谁在用：个人开发者、Anthropic 团队。
    解决什么：把"提交 PR→跑测试→生成 changelog"这类多步流程做成 Skill，命令行一键调用。
    效果：日常工程操作可重复、可分享、可版本化。
  5. 教学与作业辅助（本次作业的元场景）
    谁在用：开发者、课程设计者。
    解决什么：把"如何为任意概念生成结构化学习资料"做成 Skill，AI 在面对新概念时按统一框架输出。
    效果：同一次实现中可生成 Agent / 上下文 / Skill 三份资料，框架一致，质量稳定。

6. 概念辨析

6.1 它是什么 / 不是什么

Skill 是：用文件夹组织的、可被 Agent 按需加载的"工作手册"，包含指令、脚本、参考资源。

Skill 不是：永久占据上下文的 system prompt、独立的 AI 模型、也不只是"提示词模板"。它是模块化、可发现、可执行的复合体。

6.2 易混对照表（Prompt / Project / Subagent / MCP / Skill）

维度PromptProjectSubagentMCPSkill
作用一次性指令带上下文的会话空间独立执行任务的子 AI连接外部数据/工具的协议沉淀做事方法的能力包
持久性不跨会话跨会话按需创建长期运行长期保存，可版本化
占上下文每次占用知识库可 RAG 扩展独立窗口不占（按需调用）按需加载，不命中不占
类比口头指令专属办公室外包同事USB 接口工作手册 + 工具箱
何时选一次性对话持续主题工作需要隔离的子任务接外部数据源重复性 + 需一致性的工作

6.3 适用前提与失效条件

适用场景：工作流反复出现 / 团队需要统一标准 / 任务对一致性要求高 / 涉及代码或文件操作。
不适用：
  • 一次性探索性对话（用 Prompt 即可）
  • 每次任务路径都不一样的开放式问题（无法模板化）
  • 纯知识问答（用 Project + RAG 更合适）
  • 需要独立隔离环境的并行任务（用 Subagent）

6.4 常见误解

  • 误解 1："Skill 就是包装了一下 prompt"。纠正：Skill 是带目录结构 + 描述路由 + 可执行脚本的复合体，且默认不占上下文——这两点 prompt 都做不到。
  • 误解 2："Skill 越多越好"。纠正：每个 Skill 的 description 都会被扫描用于匹配，太多反而拖慢路由、增加误触发，要做"少而精"。
  • 误解 3："Skill 可以替代工具调用"。纠正：Skill 是"做事的方法"，要做事仍要工具（API / 文件系统 / 代码执行）。Skill 与 MCP（连接数据/工具）配合，不是替代。
  • 误解 4："Skill 是 Claude 独有的概念"。纠正：Anthropic 把它打包成产品形态，但"模块化提示 + 文件系统加载"在 LangChain、Cursor 等产品中都有类似思想。Anthropic 的贡献是把它标准化、跨平台化。

7. 自测题

Q1（概念复述）：用一句话向同事解释"AI Skill 是什么"。

参考答案：Skill 是给 AI 的"工作 SOP 手册"——一个文件夹里装着"何时用、怎么用、配什么脚本"的说明，AI 在接到相关任务时按需加载，按手册执行。

Q2（结构理解）：一个标准的 Skill 至少需要什么文件？该文件最关键的两个字段是什么？

参考答案：至少需要 SKILL.md（YAML 元数据 + Markdown 指令）。最关键的两个字段是 name（技能名）和 description（触发条件 + 用途），Agent 靠 description 判断要不要加载。

Q3（应用判断）：团队每周都让 AI 按固定格式写周报，应该用什么机制？

参考答案：用 Skill。把"周报模板、章节顺序、收尾要求"写成 SKILL.md，AI 每次接到"写周报"任务时自动加载、按模板出稿。比起每次都贴一大段 prompt，Skill 既省上下文，又能保证格式统一、新人也能立刻用上。

Q4（边界辨析）：有人说"有了 Skill 就不需要 system prompt 了"。对吗？为什么？

参考答案：不对。System prompt 管的是 AI 的"人设/全局规则"（如"你是专业客服、永远用敬语"），是每次会话都生效的固定身份；Skill 管的是"做某类事的方法"，是按需加载的模块。两者层次不同：身份设定 + 多个专项能力手册 = 完整的 Agent 配置。

Q5（元思考）：观察本作业项目中的 .workbuddy/skills/concept-study-pack/SKILL.md，它体现了 Skill 的哪些核心属性？

参考答案：体现了 (1) Composable：可与其它 Skill 并存；(2) Portable：纯文本 + Markdown，可跨 WorkBuddy / Claude Code / API 使用；(3) Efficient：默认不占上下文，按 description 触发时加载；(4) Powerful：含自检要求与生成步骤，结构化产 HTML。YAML 元数据里 name: concept-study-pack 和 description 是触发入口；正文则规定了输入信息、输出结构、来源要求等"工作手册"内容。
